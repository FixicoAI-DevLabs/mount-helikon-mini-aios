## Support boundaries beyond the published project beta

The project profile is demonstrated only within the recorded browser/Pro/GPT-5.6 Sol conditions. Ordinary global-chat automatic exact-source delivery and free-account behavior are unresolved. This project route is an explicitly limited evaluation alternative, not a silent replacement of the original ordinary-chat/free-account goal.

Bounded copies recovered the entire candidate-4 source exactly. The host did not expose a hidden complete-body read trace in each ordinary turn. The strict evidence validator's positive-run source fields therefore remain unasserted; they must not be fabricated to obtain a pass. Historical full Helikon trace limitations are not reopened through guessed interfaces.

The utility pilot does not demonstrate general benefit over a concise baseline. Candidate 4 tied the concise baseline at 22/24 reviewed tasks and produced about 10% more output characters; costs and host context were not fully observable. Planning repairs have targeted fresh tests, whose scope is kept separate from the historical comparison.

The user's production full Helikon settings, Skills, memories and unrelated projects were preserved. Publication was explicitly approved, PR #9 was merged, and the exact tested package was published as a project prerelease. The release workflow verified the public downloads and tag target. A fresh post-publication ChatGPT browser installation check was unavailable; it is not silently counted as another completed test. Updating old users' account installations is outside this task.

See the reports under `release/` for actual prompts, responses, failures, repairs, capture-fidelity notes and limitations. Protocol JSON retains `status: not_run` as a reusable specification, not a claim that historical pilots did not occur. An empty evidence template stays unrun. Static CLI results explicitly state that live behavior is not evaluated by that command.
